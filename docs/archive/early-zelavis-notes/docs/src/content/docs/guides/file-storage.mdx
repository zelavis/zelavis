Zelavis includes a powerful file storage system that works seamlessly across browsers, servers, and edge environments. Files are stored separately from documents, with documents containing lightweight references.

## Key Features

- 🌐 **Universal** - Works in browser (IndexedDB), Node/Bun (filesystem), S3, Cloudflare R2
- 📱 **Offline-First** - Store files locally in browser, auto-sync when online
- 🔒 **Type-Safe** - Schema validation for file references
- 🚀 **Production-Ready** - Size limits, MIME validation, checksums
- 🎯 **Zero-Config** - Works out of the box with sensible defaults

## Architecture

Zelavis uses a **dual-storage architecture** for optimal performance:

### Storage Layers

1. **Metadata Storage** (Database)

   - File metadata (name, size, MIME type, upload date)
   - Stored in the same database as documents
   - Fast queries, indexing, and replication

2. **File Data Storage** (Blob Storage)
   - Actual file bytes (images, videos, audio, documents)
   - Stored in separate object storage (S3, R2, filesystem, IndexedDB)
   - Optimized for large binary data

### How It Works

Documents store **file references** (metadata), not the actual files:

```typescript
{
  id: "song-123",
  title: "My Song",
  audio: {
    id: "file-abc123",           // File ID in blob storage
    url: "/zelavis/files/...",  // URL to access file
    name: "song.mp3",
    size: 3145728,               // 3MB
    mimeType: "audio/mpeg",
    uploadedAt: "2025-12-28T..."
  }
}
```

This keeps documents lightweight, queryable, and replicable while storing large files separately in appropriate storage systems (S3 for cloud, filesystem for servers, IndexedDB for browsers).

## Storage Drivers

Zelavis automatically selects the right storage driver based on your environment:

| Environment     | Default Driver | File Storage Location |
| --------------- | -------------- | --------------------- |
| **Browser**     | IndexedDB      | Browser's IndexedDB   |
| **Node.js/Bun** | Memory\*       | In-memory (warning)   |
| **Custom**      | S3/R2/etc      | User-configured       |

\*Server environments require explicit filesystem configuration (see below).

### Auto-Detection (Browser Only)

No configuration needed in the browser - Zelavis automatically uses IndexedDB:

```typescript
const db = new Zelavis({
  adapter: adapter_bun_server(),
  // Browser: IndexedDB auto-detected
  // Server: Memory (with warning - configure filesystem explicitly)
});
```

### Memory Driver (Testing)

For unit tests and development:

```typescript
const db = new Zelavis({
  adapter: adapter_bun_server(),
  fileStorage: {
    driver: "memory", // In-memory storage (not persisted)
  },
});
```

### Filesystem Driver (Self-Hosted)

**Required for server persistence.** Import and configure explicitly:

```typescript
import fsDriver from "unstorage/drivers/fs";

const db = new Zelavis({
  adapter: adapter_bun_server(),
  fileStorage: {
    driver: fsDriver({ base: "./uploads" }), // Must pass driver instance
  },
});
```

### S3-Compatible Storage (Cloud)

For AWS S3, MinIO, or any S3-compatible storage:

```typescript
import s3Driver from "unstorage/drivers/s3";

const db = new Zelavis({
  adapter: adapter_bun_server(),
  fileStorage: {
    driver: s3Driver({
      accessKeyId: process.env.S3_ACCESS_KEY,
      secretAccessKey: process.env.S3_SECRET_KEY,
      bucket: "my-app-files",
      region: "us-east-1",
    }),
  },
});
```

### Cloudflare R2

For Cloudflare R2 (S3-compatible):

```typescript
import { S3Client } from "@aws-sdk/client-s3";
import s3Driver from "unstorage/drivers/s3";

const s3Client = new S3Client({
  region: "auto",
  endpoint: `https://${process.env.CF_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId: process.env.R2_ACCESS_KEY_ID,
    secretAccessKey: process.env.R2_SECRET_ACCESS_KEY,
  },
});

const db = new Zelavis({
  adapter: adapter_bun_server(),
  fileStorage: {
    driver: s3Driver({ client: s3Client, bucket: "my-bucket" }),
  },
});
```

### Custom Drivers

You can use any [unstorage driver](https://unstorage.unjs.io/drivers):

```typescript
import azureDriver from "unstorage/drivers/azure-storage-blob";
import gcsDriver from "unstorage/drivers/google-cloud-storage";

// Azure Blob Storage
const db = new Zelavis({
  fileStorage: {
    driver: azureDriver({
      /* config */
    }),
  },
});

// Google Cloud Storage
const db = new Zelavis({
  fileStorage: {
    driver: gcsDriver({
      /* config */
    }),
  },
});
```

## Quick Start

### 1. Initialize Zelavis

```typescript
import { Zelavis, adapter_bun_server } from "zelavis";

const db = new Zelavis({
  adapter: adapter_bun_server(),
  // File storage auto-detected:
  // - Browser: IndexedDB
  // - Server: Filesystem (./data/files/)
  // Or configure explicitly:
  fileStorage: {
    driver: "memory", // for testing
    maxFileSize: 10_000_000, // 10MB limit
    allowedMimeTypes: ["image/*", "application/pdf"], // optional
  },
});
```

### 2. Upload a File

```typescript
const file = document.querySelector('input[type="file"]').files[0];
const buffer = await file.arrayBuffer();

const metadata = await db.files.upload(buffer, {
  name: file.name,
  mimeType: file.type,
});

console.log(metadata);
// {
//   id: "file-1234...",
//   name: "photo.jpg",
//   size: 524288,
//   mimeType: "image/jpeg",
//   uploadedAt: "2025-12-28T...",
//   checksum: "abc123...",
//   syncStatus: "synced"
// }
```

### 3. Create Collection with File Schema

```typescript
await db.createCollection((s) => ({
  collectionName: "posts",
  schema: {
    title: s.string({ minLength: 1 }),
    content: s.string(),
    coverImage: s.image({ optional: true }),
    attachments: s.array(s.pdf({ optional: true })),
  },
}));
```

### 4. Insert Document with File Reference

```typescript
await db.insert(() => ({
  into: "posts",
  values: {
    title: "My Post",
    content: "Post content...",
    coverImage: {
      id: metadata.id,
      name: metadata.name,
      url: db.files.getUrl(metadata.id),
      size: metadata.size,
      mimeType: metadata.mimeType,
      uploadedAt: metadata.uploadedAt,
    },
  },
}));
```

## File Storage API

### `db.files.upload(buffer, metadata)`

Upload a file to storage.

**Parameters:**

- `buffer` - `ArrayBuffer | Uint8Array` - File contents
- `metadata` - Object with:
  - `name` - `string` - Filename
  - `mimeType` - `string` - MIME type
  - `id?` - `string` - Optional custom ID

**Returns:** `Promise<FileMetadata>`

```typescript
const metadata = await db.files.upload(buffer, {
  name: "document.pdf",
  mimeType: "application/pdf",
});
```

### `db.files.download(id)`

Download a file from storage.

**Parameters:**

- `id` - `string` - File ID

**Returns:** `Promise<{ buffer: ArrayBuffer, metadata: FileMetadata }>`

```typescript
const { buffer, metadata } = await db.files.download("file-123");
const blob = new Blob([buffer], { type: metadata.mimeType });
```

### `db.files.delete(id)`

Delete a file from storage.

**Parameters:**

- `id` - `string` - File ID

**Returns:** `Promise<void>`

```typescript
await db.files.delete("file-123");
```

### `db.files.list()`

List all files in storage.

**Returns:** `Promise<FileMetadata[]>`

```typescript
const files = await db.files.list();
files.forEach((file) => {
  console.log(`${file.name} - ${file.size} bytes`);
});
```

### `db.files.getMetadata(id)`

Get file metadata without downloading.

**Parameters:**

- `id` - `string` - File ID

**Returns:** `Promise<FileMetadata | null>`

```typescript
const metadata = await db.files.getMetadata("file-123");
if (metadata) {
  console.log(`File size: ${metadata.size} bytes`);
}
```

### `db.files.getUrl(id)`

Get public URL for a file.

**Parameters:**

- `id` - `string` - File ID

**Returns:** `string`

```typescript
const url = db.files.getUrl("file-123");
// Returns: "/zelavis/files/file-123" or CDN URL
```

## Schema Types

Zelavis provides specialized schema types for file references:

### Generic File Reference

```typescript
s.fileRef(opts?: {
  mimeTypes?: string[],
  maxSize?: number,
  optional?: boolean
})
```

**Example:**

```typescript
attachment: s.fileRef({
  mimeTypes: ["application/pdf", "application/msword"],
  maxSize: 5_000_000, // 5MB
  optional: true,
});
```

### Image Files

```typescript
s.image(opts?)  // Supports: JPEG, PNG, GIF, WebP
s.jpg(opts?)    // JPEG only
s.png(opts?)    // PNG only
```

**Example:**

```typescript
await db.createCollection((s) => ({
  collectionName: "gallery",
  schema: {
    title: s.string(),
    photo: s.jpg(),
    thumbnail: s.png({ optional: true }),
  },
}));
```

### Audio Files

```typescript
s.audio(opts?)  // Supports: MP3, WAV, OGG
s.mp3(opts?)    // MP3 only
```

**Example:**

```typescript
await db.createCollection((s) => ({
  collectionName: "songs",
  schema: {
    title: s.string(),
    artist: s.string(),
    audioFile: s.mp3(),
    duration: s.number({ min: 0 }),
  },
}));
```

### Video Files

```typescript
s.video(opts?)  // Supports: MP4, WebM, OGG
s.mp4(opts?)    // MP4 only
```

**Example:**

```typescript
await db.createCollection((s) => ({
  collectionName: "videos",
  schema: {
    title: s.string(),
    videoFile: s.mp4(),
    thumbnail: s.jpg({ optional: true }),
  },
}));
```

### Document Files

```typescript
s.pdf(opts?)  // PDF documents
```

**Example:**

```typescript
await db.createCollection((s) => ({
  collectionName: "documents",
  schema: {
    title: s.string(),
    document: s.pdf(),
    pages: s.number({ min: 1, int: true }),
  },
}));
```

## Offline Sync

In browser environments, files can be stored locally and automatically synced when online.

### How It Works

1. **Offline**: Files stored in IndexedDB with `syncStatus: 'pending'`
2. **Goes Online**: Automatic sync to server endpoint
3. **Success**: `syncStatus` changes to `'synced'`

### Configuration

```typescript
const db = new Zelavis({
  adapter: adapter_browser(),
  fileStorage: {
    driver: "indexeddb",
    enableOfflineSync: true,
    syncEndpoint: "https://api.myapp.com/zelavis/api/files/sync",
  },
});

// Upload while offline
const metadata = await db.files.upload(buffer, {
  name: "photo.jpg",
  mimeType: "image/jpeg",
});

console.log(metadata.syncStatus); // 'pending'

// When online, automatically syncs
// syncStatus becomes 'synced'
```

### Manual Sync Check

```typescript
const files = await db.files.list();
const pendingFiles = files.filter((f) => f.syncStatus === "pending");
console.log(`${pendingFiles.length} files waiting to sync`);
```

## Complete Example

Here's a complete example of a music library with file storage:

```typescript
import { Zelavis, adapter_bun_server } from "zelavis";

// Initialize database
const db = new Zelavis({
  adapter: adapter_bun_server(),
  fileStorage: {
    driver: "fs",
    driverOptions: { base: "./music-files" },
    maxFileSize: 50_000_000, // 50MB
    allowedMimeTypes: ["audio/mpeg", "image/jpeg"],
  },
});

// Create collection
await db.createCollection((s) => ({
  collectionName: "songs",
  schema: {
    title: s.string({ minLength: 1 }),
    artist: s.string(),
    album: s.string({ optional: true }),
    audio: s.mp3(),
    coverArt: s.jpg({ optional: true }),
    duration: s.number({ min: 0 }),
    releaseYear: s.number({ min: 1900, max: 2100, int: true }),
  },
}));

// Upload audio file
const audioBuffer = await Bun.file("./song.mp3").arrayBuffer();
const audioMeta = await db.files.upload(audioBuffer, {
  name: "my-song.mp3",
  mimeType: "audio/mpeg",
});

// Upload cover art
const coverBuffer = await Bun.file("./cover.jpg").arrayBuffer();
const coverMeta = await db.files.upload(coverBuffer, {
  name: "cover.jpg",
  mimeType: "image/jpeg",
});

// Insert song with file references
await db.insert(() => ({
  into: "songs",
  values: {
    title: "My Favorite Song",
    artist: "The Band",
    album: "Greatest Hits",
    audio: {
      id: audioMeta.id,
      name: audioMeta.name,
      url: db.files.getUrl(audioMeta.id),
      size: audioMeta.size,
      mimeType: audioMeta.mimeType,
      uploadedAt: audioMeta.uploadedAt,
    },
    coverArt: {
      id: coverMeta.id,
      name: coverMeta.name,
      url: db.files.getUrl(coverMeta.id),
      size: coverMeta.size,
      mimeType: coverMeta.mimeType,
      uploadedAt: coverMeta.uploadedAt,
    },
    duration: 180,
    releaseYear: 2024,
  },
}));

// Query songs
const songs = await db.select(({ songs }) => ({ from: "songs" }));

// Play song
const { buffer } = await db.files.download(songs[0].audio.id);
const audioBlob = new Blob([buffer], { type: "audio/mpeg" });
const audioUrl = URL.createObjectURL(audioBlob);
const audio = new Audio(audioUrl);
audio.play();
```

## Best Practices

### 1. Store References, Not Files

❌ **Don't do this:**

```typescript
{
  title: "My Document",
  fileData: "<base64-encoded-10MB-file>" // ❌ Bloats document
}
```

✅ **Do this:**

```typescript
{
  title: "My Document",
  file: {
    id: "file-123",
    url: "/files/file-123",
    size: 10485760,
    mimeType: "application/pdf"
  }
}
```

### 2. Set Appropriate Limits

```typescript
fileStorage: {
  maxFileSize: 10_000_000, // 10MB for images
  allowedMimeTypes: ['image/jpeg', 'image/png']
}
```

### 3. Use Specialized Types

```typescript
// ✅ Specific type validation
coverImage: s.jpg();

// ⚠️ Less specific
coverImage: s.fileRef();
```

### 4. Handle Upload Errors

```typescript
try {
  const metadata = await db.files.upload(buffer, { name, mimeType });
} catch (error) {
  if (error.message.includes("exceeds maximum")) {
    console.error("File too large");
  } else if (error.message.includes("not allowed")) {
    console.error("File type not allowed");
  }
}
```

### 5. Clean Up Orphaned Files

```typescript
// Delete file when deleting document
const doc = await db.select(() => ({ from: "posts" }));
await db.files.delete(doc[0].coverImage.id);
await db.delete(() => ({ from: "posts", where: eq("id", doc[0].id) }));
```

## Security Considerations

### File Size Limits

Always set `maxFileSize` to prevent abuse:

```typescript
fileStorage: {
  maxFileSize: 10_000_000; // 10MB
}
```

### MIME Type Validation

Restrict allowed file types:

```typescript
fileStorage: {
  allowedMimeTypes: ["image/jpeg", "image/png", "application/pdf"];
}
```

### Checksums

Files automatically include SHA-256 checksums for integrity verification:

```typescript
const metadata = await db.files.upload(buffer, { name, mimeType });
console.log(metadata.checksum); // "abc123..."

// Verify on download
const { buffer: downloaded, metadata: meta } = await db.files.download(id);
const newChecksum = await calculateChecksum(downloaded);
if (newChecksum !== meta.checksum) {
  throw new Error("File corrupted");
}
```

### Access Control

File endpoints are currently unauthenticated. For production:

1. Add authentication middleware to file routes
2. Check user permissions before upload/download
3. Use signed URLs for temporary access
4. Consider CDN with access controls

## Troubleshooting

### Files Not Uploading

1. Check file size limits
2. Verify MIME type is allowed
3. Check storage driver configuration
4. Ensure sufficient disk space/storage quota

### Offline Sync Not Working

1. Verify `enableOfflineSync: true`
2. Check `syncEndpoint` is correct
3. Ensure online event listener is active
4. Check browser console for errors

### Files Not Loading

1. Verify file ID is correct
2. Check file hasn't been deleted
3. Ensure storage driver is properly configured
4. Check network connectivity

### Large Files Causing Issues

1. Set appropriate `maxFileSize` limit
2. Consider chunked uploads for very large files
3. Use CDN for file delivery
4. Implement progressive loading

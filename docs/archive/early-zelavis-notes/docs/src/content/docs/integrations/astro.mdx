---
title: Astro Integration
description: How to integrate Zelavis with Astro
---

Zelavis works seamlessly with Astro through its JSON API, exposing all database operations as REST endpoints.

## Setup

### 1. Enable SSR

Configure Astro for server-side rendering in `astro.config.mjs`:

```javascript
import { defineConfig } from "astro/config";

export default defineConfig({
  output: "server",
});
```

### 2. Create Zelavis Instance

Create a shared Zelavis instance in `src/lib/db.ts`:

```typescript
import { Zelavis } from "zelavis";
import { adapter_node_server } from "zelavis/server/adapter-node";
import fsDriver from "unstorage/drivers/fs";

export const db = new Zelavis({
  adapter: adapter_node_server(),
  fileStorage: {
    driver: fsDriver({ base: "./data/uploads" }),
  },
});
```

### 3. Create API Catch-All Route

Create `src/pages/api/[...slugs].ts` to handle all Zelavis JSON API requests:

```typescript
import { db } from "../../lib/db";

const handle = ({ request }: { request: Request }) => db.app.fetch(request);

export const GET = handle;
export const POST = handle;
export const PUT = handle;
export const DELETE = handle;
```

## Using the JSON API

All Zelavis operations are now available via REST endpoints at `/api/*`:

### Collections

```bash
# Create collection
POST /api/collections
Content-Type: application/json

{
  "name": "users",
  "schema": {
    "name": { "type": "string" },
    "email": { "type": "string" }
  }
}

# List collections
GET /api/collections

# Delete collection
DELETE /api/collections/users
```

### Documents

```bash
# Insert document
POST /api/collections/users/documents
Content-Type: application/json

{
  "name": "Alice",
  "email": "alice@example.com"
}

# Query documents
GET /api/collections/users/documents?filter[name]=Alice

# Update document
PUT /api/collections/users/documents/{id}
Content-Type: application/json

{
  "email": "newemail@example.com"
}

# Delete document
DELETE /api/collections/users/documents/{id}
```

### File Uploads

```bash
# Upload file
POST /api/files
Content-Type: multipart/form-data

file=@image.jpg&collectionName=users&documentId=123

# Download file
GET /api/files/{fileId}
```

## Client-Side Usage

Use the JSON API from your Astro pages or components:

```astro
---
// src/pages/users.astro
const response = await fetch('/api/collections/users/documents');
const users = await response.json();
---

<div>
  <h1>Users</h1>
  <ul>
    {users.map(user => (
      <li>{user.name} - {user.email}</li>
    ))}
  </ul>
</div>
```

## Forms with JSON API

Instead of traditional form submissions, use JavaScript to post to the JSON API:

```astro
<form id="createUser">
  <input name="name" required />
  <input name="email" type="email" required />
  <button type="submit">Create User</button>
</form>

<script>
  document.getElementById('createUser')?.addEventListener('submit', async (e) => {
    e.preventDefault();
    const formData = new FormData(e.target as HTMLFormElement);
    const data = Object.fromEntries(formData.entries());

    const response = await fetch('/api/collections/users/documents', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data)
    });

    if (response.ok) {
      window.location.reload();
    }
  });
</script>
```

## Prefix Configuration

If you place the Zelavis endpoint in a nested path (e.g., `pages/db/[...slugs].ts`), configure the prefix:

```typescript
// src/lib/db.ts
export const db = new Zelavis({
  adapter: adapter_node_server(),
  prefix: "/db", // Match your file location
  fileStorage: {
    driver: fsDriver({ base: "./data/uploads" }),
  },
});
```

## Runtime

Zelavis works best on **Bun**, but also supports Node.js through the Node adapter shown above.

```bash
# Run with Bun
bun --bun run astro dev
```

## Notes

- Zelavis follows WinterCG standards, making it compatible with Astro's server runtime
- The JSON API is automatically generated from your Zelavis configuration
- All endpoints support standard HTTP methods (GET, POST, PUT, DELETE)
- File uploads use multipart/form-data, other requests use application/json

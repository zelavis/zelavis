The Zelavis JSON API provides a complete HTTP interface for working with Zelavis from any language or platform. This is the foundation for:

- **Building SDKs** for Python, Ruby, Go, PHP, JavaScript, and other languages
- **Creating dashboards** and admin panels with direct HTTP access
- **Server-to-server replication** between Zelavis instances
- **Cross-platform integrations** where the TypeScript SDK isn't available

All API endpoints are available at `/zelavis/api/json/*` and accept/return JSON.

## Base URL

```
http://localhost:3000/zelavis/api/json
```

## Authentication

Currently, Zelavis JSON API endpoints are unauthenticated. Authentication will be added in a future release.

## Create Collection

Create a new collection with an optional schema definition using **Schema Expressions**.

### Endpoint

```
POST /zelavis/api/json/create-collection
```

### Request Body

```json
{
  "collectionName": "users",
  "schema": {
    "name": "s.string({ minLength: 2, maxLength: 50 })",
    "email": "s.string({ format: 'email' })",
    "age": "s.number({ min: 0, max: 120, int: true })",
    "isActive": "s.boolean()"
  }
}
```

### Response

```json
{
  "status": "ok",
  "message": "Collection 'users' created successfully"
}
```

### Schema Expressions

Schema expressions are string representations of Effect Schema definitions. They provide **100% compatibility** with Effect Schema and enable full schema replication.

**Key Benefits:**

- ✅ **100% Effect Schema compatible** - Express any schema feature
- ✅ **Human-readable** - Easy to read and write
- ✅ **No eval()** - Safe parser, no code execution
- ✅ **Perfect for replication** - Send schemas as strings between servers
- ✅ **Future-proof** - New schema features work automatically

#### Auto-Generated Fields

Zelavis automatically adds these fields to every document:

- `id` - Unique identifier using nanoid
- `createdAt` - ISO 8601 timestamp
- `updatedAt` - ISO 8601 timestamp

You don't need to define these in your schema.

#### String Fields

```json
{
  "name": "s.string({ minLength: 2, maxLength: 100 })",
  "email": "s.string({ format: 'email' })",
  "username": "s.string({ pattern: '^[a-zA-Z0-9_]+$' })",
  "bio": "s.string({ optional: true })"
}
```

**String Options:**

- `minLength` (number) - Minimum string length
- `maxLength` (number) - Maximum string length
- `pattern` (string) - Regular expression pattern
- `format` (string) - Built-in format validation (`'email'`, `'url'`, `'uuid'`)
- `optional` (boolean) - Allow field to be omitted

#### Number Fields

```json
{
  "age": "s.number({ min: 0, max: 120, int: true })",
  "price": "s.number({ min: 0 })",
  "rating": "s.number({ min: 1, max: 5 })",
  "discount": "s.number({ optional: true })"
}
```

**Number Options:**

- `min` (number) - Minimum value (inclusive)
- `max` (number) - Maximum value (inclusive)
- `int` (boolean) - Require integer values (no decimals)
- `optional` (boolean) - Allow field to be omitted

#### Boolean Fields

```json
{
  "isActive": "s.boolean()",
  "isVerified": "s.boolean({ optional: true })"
}
```

**Boolean Options:**

- `optional` (boolean) - Allow field to be omitted

#### Array Fields

```json
{
  "tags": "s.array(s.string(), { minItems: 1, maxItems: 5 })",
  "scores": "s.array(s.number({ min: 0, max: 100 }))",
  "flags": "s.array(s.boolean(), { optional: true })"
}
```

**Array Options:**

- `minItems` (number) - Minimum array length
- `maxItems` (number) - Maximum array length
- `optional` (boolean) - Allow field to be omitted

#### Nested Objects

```json
{
  "address": "s.object({ street: s.string(), city: s.string(), zip: s.number() })",
  "profile": "s.object({ name: s.string(), age: s.number() }, { optional: true })"
}
```

#### Unions (OR types)

```json
{
  "status": "s.union([s.literal('active'), s.literal('inactive'), s.literal('pending')])",
  "value": "s.union([s.string(), s.number()])"
}
```

#### Literals/Enums

```json
{
  "role": "s.literal(['admin', 'user', 'guest'])",
  "status": "s.literal('published')"
}
```

#### Dates

```json
{
  "birthdate": "s.date()",
  "deletedAt": "s.date({ optional: true })"
}
```

#### Records (Dynamic Keys)

```json
{
  "metadata": "s.record(s.string(), s.any())",
  "scores": "s.record(s.string(), s.number())"
}
```

#### Tuples

```json
{
  "coordinates": "s.tuple([s.number(), s.number()])",
  "rgb": "s.tuple([s.number(), s.number(), s.number()])"
}
```

#### Nullable Types

```json
{
  "middleName": "s.nullable(s.string())"
}
```

See the complete documentation at [Complete Examples](#complete-examples) below for more complex schema patterns.

## Complete Examples

### E-commerce Product

```json
{
  "collectionName": "products",
  "schema": {
    "name": "s.string({ minLength: 1, maxLength: 200 })",
    "description": "s.string({ maxLength: 2000 })",
    "price": "s.number({ min: 0 })",
    "stock": "s.number({ min: 0, int: true })",
    "inStock": "s.boolean()",
    "categories": "s.array(s.string({ minLength: 1 }), { maxItems: 10 })",
    "sku": "s.string({ pattern: '^[A-Z0-9\\\\-]+$' })",
    "status": "s.literal(['draft', 'published', 'archived'])"
  }
}
```

### Blog Post

```json
{
  "collectionName": "posts",
  "schema": {
    "title": "s.string({ minLength: 5, maxLength: 150 })",
    "slug": "s.string({ pattern: '^[a-z0-9-]+$' })",
    "content": "s.string({ minLength: 10 })",
    "excerpt": "s.string({ maxLength: 300, optional: true })",
    "published": "s.boolean()",
    "viewCount": "s.number({ min: 0, int: true })",
    "tags": "s.array(s.string(), { maxItems: 10 })",
    "author": "s.object({ name: s.string(), email: s.string({ format: 'email' }) })"
  }
}
```

### User Profile with Complex Types

```json
{
  "collectionName": "users",
  "schema": {
    "username": "s.string({ minLength: 3, maxLength: 30, pattern: '^[a-zA-Z0-9_]+$' })",
    "email": "s.string({ format: 'email' })",
    "fullName": "s.string({ minLength: 2, maxLength: 100 })",
    "age": "s.number({ min: 13, max: 120, int: true })",
    "role": "s.literal(['admin', 'moderator', 'user', 'guest'])",
    "status": "s.union([s.literal('active'), s.literal('inactive'), s.literal('suspended')])",
    "bio": "s.string({ maxLength: 500, optional: true })",
    "interests": "s.array(s.string(), { minItems: 1, maxItems: 20 })",
    "address": "s.object({ street: s.string(), city: s.string(), country: s.string(), zip: s.string() })",
    "socialLinks": "s.record(s.string(), s.string())"
  }
}
```

```
POST /zelavis/api/json/collection-exists
```

```json
{
  "collectionName": "users"
}
```

```json
{
  "status": "ok",
  "exists": true,
  "collectionName": "users"
}
```

## Insert Document

Insert a single document or multiple documents into a collection.

### Endpoint

```
POST /zelavis/api/json/insert
```

### Request Body

**Single Document:**

```json
{
  "into": "users",
  "values": {
    "name": "John Doe",
    "email": "john@example.com",
    "age": 30,
    "isActive": true
  }
}
```

### Response

```json
{
  "status": "ok",
  "inserted": 1,
  "documents": [
    {
      "id": "abc123",
      "name": "John Doe",
      "email": "john@example.com",
      "age": 30,
      "isActive": true,
      "createdAt": "2025-12-28T10:30:00.000Z",
      "updatedAt": "2025-12-28T10:30:00.000Z"
    }
  ]
}
```

## Server-to-Server Replication

Schema expressions enable seamless replication:

```typescript
// Server A creates collection
await fetch("http://server-a:3000/zelavis/api/json/create-collection", {
  method: "POST",
  body: JSON.stringify({
    collectionName: "products",
    schema: {
      name: "s.string({ minLength: 1 })",
      price: "s.number({ min: 0 })",
    },
  }),
});

// Server B replicates with exact same schema
// Schema expressions are 100% compatible - no data loss
```

## Building SDKs

Example Python SDK:

```python
class Zelavis:
    def create_collection(self, name, schema):
        return requests.post(
            f"{self.api}/create-collection",
            json={"collectionName": name, "schema": schema}
        ).json()

# Usage
db.create_collection("users", {
    "name": "s.string({ minLength: 2 })",
    "email": "s.string({ format: 'email' })"
})
```

## Best Practices

1. **Use literals for fixed values**: `"status": "s.literal(['active', 'inactive'])"`
2. **Set array limits**: `"tags": "s.array(s.string(), { maxItems: 20 })"`
3. **Use nested objects for structure**: Group related fields together
4. **Mark optional fields**: `{ optional: true }`
5. **Handle validation errors**: Check response status

## Error Handling

All endpoints return `status`:

```json
{ "status": "ok" }  // Success
{ "status": "error", "message": "..." }  // Error
```

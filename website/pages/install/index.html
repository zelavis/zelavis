Install

Install Zelavis.

One command, one installation. Whichever way you start it, you get the same paths, the same service and the same uninstall.

Shell installer

One command on a fresh Linux server or a Mac. It installs everything Zelavis needs and nothing else.

Available
bash

# Linux server (root, systemd)

curl -fsSL https://zelavis.com/install.sh | sudo sh -s -- --channel alpha

# macOS, or Linux without root

curl -fsSL https://zelavis.com/install.sh | sh -s -- --channel alpha --user
  • Needs curl and tar. It downloads about 50 MB of Node plus the Zelavis package.
  • Read it first: zelavis.com/install.sh is one short, commented script.
  • Run it again later to upgrade the same installation.

npm, pnpm or Bun create

The same installer for people who already have a JavaScript toolchain. It installs on this machine; it does not scaffold a folder.

Available
bash

# Shows the plan and the exact command, changes nothing

npm create zelavis@alpha -- --dry-run

# Install (asks for sudo on Linux when it needs it)

npm create zelavis@alpha -- --yes

# Or with pnpm

pnpm create zelavis@alpha --yes

# Or with Bun

bun create zelavis@alpha --yes
  • Your Node only runs the small create program. Zelavis always runs on its own private Node.
  • Linux with sudo installs the full system service; macOS installs for your user.
  • Same paths, same units, same receipt as the shell installer.

APT repository

A signed apt.zelavis.com repository for Debian and Ubuntu is on the roadmap. It does not exist yet.

Planned
bash

# Not available yet. Use the shell installer:

curl -fsSL https://zelavis.com/install.sh | sudo sh -s -- --channel alpha
  • When it ships it will install the same Platform through the same installer, then update with apt.
  • Until then the shell installer is the supported Linux path.

Debian package

A downloadable .deb is built from the same release tree but is not published yet.

Planned
bash

# Not available yet. Use the shell installer:

curl -fsSL https://zelavis.com/install.sh | sudo sh -s -- --channel alpha
  • There is no download link on purpose: nothing is published to install from.
  • A package will run the same installer in its post-install step.

Windows

Native Windows is not supported. A PowerShell installer is planned; for now run Zelavis inside WSL 2.

Planned
powershell

# Today: inside a WSL 2 distribution with systemd enabled

curl -fsSL https://zelavis.com/install.sh | sudo sh -s -- --channel alpha
  • Enable systemd in your WSL distribution first (set systemd=true in /etc/wsl.conf).
  • Docker Desktop and native Windows services are not part of this yet.

Alpha. The commands pick the newest alpha build. A stable channel arrives with the first stable release.

What the installer does.

It trusts exactly two places: nodejs.org for the runtime and npm for the package. There are no release keys, no bundles to unpack and no second download host.

1

Fetches a private Node

The Node version Zelavis is built for comes from nodejs.org and is checked against its published SHA-256. It never replaces the Node already on your machine.

2

Installs the exact package from npm

The version you ask for, verified by npm against the registry digest. Dependency install scripts stay off, and nothing needs a compiler: it is all plain JavaScript.

3

Lays out one installation

Releases under /opt/zelavis, data in /var/lib/zelavis, configuration in /etc/zelavis, a systemd service, a receipt, and a single zelavis command.

4

Starts safely

It prints the address to open, plus a one-time first-owner token that decides who may claim the account. The Edge proxy and the Agent stay off until you turn them on.

After it finishes.

Three things, in this order. None of them needs a configuration file.

Open the dashboard

Open the address the installer printed and finish setup with the token. It is plain HTTP until you add a hostname with HTTPS in the wizard, so claim the account straight away.

http://YOUR-SERVER-IP:3000/zelavis

Check the installation

Read-only, changes nothing, and tells you what is wrong in plain words.

sudo zelavis doctor

Add a hostname and HTTPS

The setup wizard has an optional Platform hostname step that verifies DNS before enabling HTTPS through the Edge.

zelavis setup

Requirements

  • Linux x64 or arm64 with systemd for a full server install.
  • macOS on Apple silicon or Intel, installed for your user without system services.
  • curl, tar and a normal internet connection during install.
  • Windows through WSL 2 for now; native Windows is planned.

Upgrade and remove

  • On a server, press Update now in the dashboard when a new version appears, or run zelavis update apply --wait. Anywhere else, run the same command again. A downgrade needs --allow-downgrade.
  • Preview a full removal first, then confirm it. It removes only what the installer can prove it owns.
zelavis uninstall --all --dry-run
zelavis uninstall --all --confirm DELETE-ALL-ZELAVIS-DATA

Every option and the full layout are in the installation guide.

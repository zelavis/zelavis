Managed third-party apps now have an ordinary private Zelavis App runtime with Auth, Database, Storage and Workloads available by default. Service setup exposes the native APIs, and successful API use automatically reveals the existing dashboard sections without adding a second Project card. Usage and workload state persist across recipe handovers and restarts, while the third-party app's processes and files remain untouched. Existing bound runtimes follow the qualified parent engine through the persistent host; native App engine pins stay unchanged.

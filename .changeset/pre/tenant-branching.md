Branch a Tenant: `db.branchTenant(tenant, into, { outbox })` makes `into` a new Tenant holding a copy of `tenant` as of one position of its log (records, history, definitions, projection and time-series state and idempotency receipts), taken while the source keeps taking writes and while it may be moved: only the branch is leased for the copy, the source is read a page at a time. The source's undelivered outbox messages stay with it by default (`outbox: "leave"`, retracted in the branch's own log after the branch point) or are copied with `outbox: "copy"`. The branch keeps the source's identifiers and log positions and records its lineage, so a cursor or checkpoint from before the branch point carries on in it. A divided Tenant branches into one divided the same way, part by part, each part as of its own position (per-part consistency only; there is no one moment across parts). Until a copy is whole it answers `TenantBranching`; running the branch again, or opening the database again, finishes one that was cut off. Also `POST database/tenants/:tenantId/branch` (needs `database.restore`), `client.projects.branchTenant`, `zelavis projects branch-tenant --tenant T --to NEW [--outbox leave|copy]` and a Branch action on the dashboard's Database → Tenants page. Merging a branch back is not supported.
